# 功能與計算檢視 — 2026-09-19

檢視對象：本機套件程式與已安裝的 Wealthfolio SDK 3.8.0。初次檢視版本：2.3.0。

**後續更新：**目前的 1.0.0（先前標為 2.4.0，依使用者要求重定版號）已完成持倉成本線、提醒歷史及主程式開啟期間的跨頁監控。下文保留 2.3.0 當時的檢視結果；背景行為、驗證數量與已完成建議以 [1.0.0 版本說明](release-1.0.0.md) 為準。

## 結論

原本已有持倉整合、基本技術指標、情境快篩與個股 K 線，作為日線分析工具具備基礎功能。SMA、EMA、Wilder RSI、母體標準差布林通道公式基本正確；主要問題集中於行情狀態、Pivot 定義、文件與介面功能不一致，以及例外情況缺少提示。原本僅 6 個公式測試，無資料解析、提醒、整體分析或交易紀錄測試。

本次完成使用者要求的支撐／壓力、逐檔百分比移動停利、實際買賣日期標記及線圖圖例，並修正下列可重現問題。

## 已修正的問題

| 問題 | 原本影響 | 2.3.0 行為 |
| --- | --- | --- |
| 全部日 K 固定標示 closed | 盤中價被當成完整收盤 | 依交易所日期與 regular session 結束時間分類，無法確認則標 unknown |
| Pivot 直接取最後日 K | 當天高低點持續影響當天關卡 | 固定使用最新交易日之前的已收盤日 K，顯示基準日期 |
| Classic 的 R3／S3 使用 Traditional 算式 | 同名指標與 TradingView Classic 不一致 | Classic 改為 P ± 2(H−L)，增加非對稱價格驗證 |
| 52 週快篩文件 15%、程式 5% | 使用者對篩選結果預期不同 | 統一採高低範圍兩端各 15% |
| RSI 關閉時主圖也消失 | 主圖建構錯誤依賴 RSI 容器 | 主圖和 RSI 各自建立，已操作驗證 |
| 文件列四條 SMA、兩條 EMA，但圖表各只畫 20 日 | 宣稱功能不存在 | 實作 SMA 20/60/120/240 與 EMA 12/26，加入圖例 |

| 均線位置標成「跌破／站上」 | 每天低於均線都像新事件 | 改名「低於／高於」，未宣稱新交叉 |
| 缺失 OHLC 用收盤價補成假高低點 | 影響支撐壓力與波動計算 | 異常日 K 略過並顯示提示；未知成交量保留 null |
| provider 忽略 from/to，一律固定兩年 | 呼叫契約不成立，提醒無法按起點補查 | 請求與回傳都按指定範圍，驗證 interval 與價格基準 |
| UTC 日期取代交易所日期 | 部分時區可能對錯交易日 | 依供應商交易所時區產生日期 |
| `.TWO` 與台股貨幣處理不一致 | 上櫃辨識與貨幣錯誤 | 明確後綴優先，台股回傳 TWD；不把 EUR/GBP 默認為美股 |
| 個別股票失敗只寫入主控台 | 總覽靜默少股票 | 顯示失敗標的、原因與重試入口 |
| 快速切換股票可能讓舊請求覆蓋新資料 | 標題、圖表與交易紀錄不相符 | 請求序號保護，載入時清空舊資料 |
| 空資料回傳股價 0、篩選無結果顯示沒有持倉 | 造成假報價或誤判持倉不存在 | 無行情明確失敗，篩選無結果有獨立文案 |
| 高價股票四捨五入至整數 | 部分價格比較失去細節 | 表格保留兩位小數，計算與觸發使用未四捨五入原值 |
| zip 指令要求不存在的 assets 目錄，版本號不一致 | 打包失敗或舊封裝殘留 | 建立全新封裝，套件／manifest 版本統一 2.3.0 |

Pivot 類型差異以 [TradingView 的公式定義](https://www.tradingview.com/support/solutions/43000521824-pivot-points-standard/) 為準。RSI 的比率與 30／70 門檻對照 [Fidelity 指標指南](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI)。提醒採高點回落概念，可參閱 [Fidelity 停損類型說明](https://www.fidelity.com/trading/faqs-order-types)，本套件實作的是提醒而非券商委託。

## 新功能的明確定義

### 支撐／壓力

提供兩組不同用途的參考：總覽與圖表的前 20 個已收盤交易日最低／最高價，以及以前一交易日 OHLC 計算的 Pivot 關卡。都排除目前觀察的交易日，不以未來資料回填。圖表水平線呈現目前關卡，不代表過去每一天當時可用的線；它不是回測。這些是算法定義的參考價，並非保證有效的市場轉折。

### 移動停利

依使用者確認，從啟用時開始追蹤，預設 20%，各檔可調整；可手動輸入起始高點。高點只上移，提醒價 = 高點 × (1−百分比/100)。測試案例：100 開始，之後最高 125，20% 的提醒價是 100；最新價格等於 100 即觸發。

使用日 K 最新價檢查。第一天不把啟用前既有日內高點灌入追蹤；離線後以可取得的逐日收盤補查，保留首次已知觸發日期、價格與當時門檻。無法重建沒有收盤穿越的短暫盤中穿越，也無法精確知道啟用當天未被輪詢觀察到的局部高點。這是日線與輪詢資料的限制。

套件頁面存在時輪詢，無永久背景程序或系統通知；提示透過主程式 toast 與持續清單。確認不清除紀錄、反彈不清除紀錄，改百分比不降低高點，手動重新開始才清除觸發。拆股／併股期間避免直接將舊高點與新價格比較，需確認並重設。

設定使用 SDK 的持久儲存。操作排隊避免同一頁面內的存檔互相覆蓋；損毀資料不自動覆寫，儲存失敗不假裝成功。不提供跨多台裝置同時編輯的合併保證。

### 買賣點與圖例

使用 `activities.getAll` 讀取交易，篩選相同股票／貨幣的 BUY、SELL 與可用成交資料。排除 PENDING／DRAFT／VOID 和待確認紀錄；相同交易 ID 去重。舊 SDK 未帶 status 時視為舊式有效紀錄。

以記錄日期畫買入向上、賣出向下箭頭，文字含數量與成交價。箭頭靠近日 K 上下緣，其垂直位置不是成交價座標；真實價格看標籤及交易表。表格也保留圖表兩年範圍外或無行情當天的紀錄。保留原始成交價，不將拆股前交易誤稱為已還原成本。

## 驗證與限制

- 原有 6 測試擴充至 48 個：基本公式與參數、Classic 與 Traditional 差異、混合漲跌 RSI、前期支撐壓力、資料解析、盤中／收盤、時區、日期排序／去重、標的辨識、買賣篩選、停利邊界、離線補查、拆股、儲存錯誤、同步存檔、提醒去重與重新開始。
- TypeScript 檢查包含正式程式、測試與預覽。
- 在本機合成資料頁面操作檢查：個股買賣箭頭、圖例、RSI 開關、SMA／EMA／布林、Fibonacci、手動高點觸發、確認與重新追蹤。390px 視窗檢查無整頁橫向溢出，表格保留自身橫向捲動。
- 正式主程式尚未重新安裝此封裝；未對使用者真實交易、權限授予或即時 Yahoo 連線進行端到端驗證。預覽不能代替這一步。
- Yahoo 網路或接口變動、缺資料、資料更正、價格還原方式，仍可能改變指標。設定與畫面明示日期，沒有保證即時行情或無遺漏提醒。
- 除權息未做總報酬還原；價格回落提醒可能受到除息影響。拆股已有暫停保護。
- 主頁資料以手動重新整理更新，提醒清單獨立輪詢；兩者時間可能不同。已平倉的提醒不自動刪除。
- 台股名稱資料庫是靜態快照；新上市、改名、轉板仍需更新。只針對台灣上市／上櫃與美股設計，不覆蓋所有海外市場。
- 原有 lint 尚無 ESLint 配置；未宣稱 lint 通過。

## 2.3.0 當時建議的下一步（完成進度見 1.0.0 版本說明）

1. **提醒事件紀錄與資料新鮮度規則。** 把觸發、確認、重設與資料缺口保留成歷史，方便回頭確認提醒當時看到了什麼；交易日曆可區分休市與資料過期。優先於再加更多指標。
2. **持倉成本線與報酬分解。** 同時呈現目前部位平均成本、含／不含手續費報酬，明確區分外幣價格變化與匯率。先確認主程式成本基準和拆股處理，不從現有零散交易直接假設 FIFO。
3. **可選的波動度停利。** 加入 ATR 倍數作為百分比以外的提醒方式，讓使用者比較不同股性的門檻；保留百分比預設，不自動替使用者改風險設定。
4. **真正的背景監控。** 如果需求是關閉頁面也要提示，需獨立的排程／主程式服務與可靠行情源，另處理系統通知權限、休眠與失敗重試；不能只增加網頁計時器就宣稱完成。
5. **不同期間關卡與成交量確認。** 在目前 20 日關卡之外提供 60 日區間、週線 Pivot，以及突破／跌破「事件」而非單純位置；需增加對照資料與避免未來資料的測試。

如之後要統一套件介面規格，可選用 `$impeccable init` 建立產品與設計背景；本次沿用既有介面，未將此步驟當成修改前提。
