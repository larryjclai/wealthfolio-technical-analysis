# Wealthfolio Technical Analysis

台股／美股持倉技術分析擴充套件。目前版本 **1.0.1**，包含持倉成本線、提醒歷史、每日收盤檢查、支撐／壓力、逐檔移動停利、真實買賣紀錄與顏色圖例。本版依使用者要求移除背景輪詢、減少休市空白資料警告，並保留個股往返時的總覽狀態。

## 功能

- 讀取有效、未封存帳戶的證券持倉，跨帳戶合併相同 Yahoo 代碼。總覽隱藏持有股數，個股頁才顯示。
- 總覽進入個股再返回時沿用行情、篩選、排序及捲動位置；重新開啟套件／App 或按「重新整理」才重新載入。
- 持倉總覽：最新日 K 價格、相對前一筆有效日 K 漲跌、SMA 20／60／120／240、RSI 14、52 週位置與九種快篩。可排序股票、最新價、漲跌、RSI、52 週位置與訊號數。
- 支撐／壓力：以前 20 個已收盤交易日最低／最高價計算，不含圖表最新交易日；不足 20 日留空。突破後不自動互換角色。
- 日 K 圖：四條 SMA、EMA 12／26、布林通道 20／2、RSI 14（含 30／70 參考線）、支撐／壓力與停利提醒線。每條線都有圖例及價格軸標示。
- Pivot：Classic／Fibonacci 可切換，以最新交易日之前的已收盤日 K 為基準。不是下一交易日的預估值。
- 買賣點：讀取所有帳戶的已入帳 BUY／SELL，依記錄日期畫箭頭，附股數與原始成交價，下方列出帳戶及交易表。不在行情日期中的交易留在表內，不移到相鄰交易日。
- 持倉成本線：白色虛線與獨立開關，採同幣別各帳戶剩餘帳面成本總和 ÷ 股數總和。顯示股數、帳戶數與資料日，成本缺漏、空頭或幣別不符時不畫線。
- 提醒歷史：記錄啟用、修改、觸發、確認、重設、停用、行情失敗／恢復；可依股票與事件篩選。舊版監控暫停／恢復事件仍保留。
- 台股名稱與上市／上櫃對應使用隨套件附上的資料快照；明確 `.TW`／`.TWO` 後綴優先。
- 可從總覽的「查詢股票」查看非持倉股票並設定提醒。

## 移動停利

1. 開啟個股圖表，輸入回落百分比（大於 0、小於 100，例如 20）。
2. 起始高點留空時，先取得新行情，從最近已收盤日 K 的收盤價開始。亦可手動指定不低於該收盤價的起始高點。
3. 持續保存追蹤高點，只升不降。提醒價 = 高點 × (1 − 回落百分比 ÷ 100)。例如高點 125、回落 20%，提醒價為 100。
4. 起始參考日的高點可能早於啟用，預設只使用該日收盤價；往後已收盤交易日使用日 K 最高價更新高點。未收盤與收盤狀態未知的日 K 不參與提醒評估。
5. 已收盤日 K 的 `close` 小於或等於提醒價時觸發。關閉後重開會依日期補查可取得的日 K 收盤，不使用日內最低價推定先後順序。
6. 觸發會顯示套件提醒與持續保留的紀錄。確認提醒不會重置追蹤；價格反彈也不抹除紀錄。修改百分比保留高點，「重新開始追蹤」會重設本次觸發狀態並更換高點基準，過去事件仍保留在提醒歷史。
7. 偵測追蹤期間拆股／併股時暫停評估，請核對價格後重新開始。設定透過 Wealthfolio SDK 的持久儲存保存，儲存失敗不會顯示成功。

**每日檢查範圍：**開啟或回到套件時，依各股票交易所當地日期，每天自動掃描一次最近已收盤日 K；成功掃描日期會保存，當天重開 App 也不重複抓提醒行情。沒有背景計時器，不在其他頁面持續抓價。沒有新收盤資料的休市日沿用上一交易日，不重複觸發同一輪提醒。行情失敗不計入成功掃描，可重新進入或手動重試。

如果今日首次檢查在收盤前，只會掃描之前已收盤的日 K；收盤後可按「立即檢查日 K」強制再查，否則等下次日期變更後進入／回到套件。長時間停留不會自動按時檢查。離線後會補查可取得的漏查收盤；主程式未開啟時不會發通知。這是價格提醒，不是券商委託，也不保證獲利。持倉賣完後請自行停用該股票提醒。

## 成本與提醒歷史

成本直接使用 Wealthfolio 的 `costBasis.local` 與目前剩餘股數，不重算 FIFO 或將原始買賣價當成成本；手續費、拆股與批次成本處理依主程式。白色虛線代表目前持倉均價，不代表每個歷史日期的成本。不同帳戶的資料日若不一致會提示；同步持倉後重新載入可更新。

歷史保存最近 300 筆內且符合儲存容量的事件，超過時移除最舊事件並顯示累計數量。每筆分開呈現記錄時間、行情日、價格／高點快照及門檻；行情失敗使用上次有效快照，連續失敗不重複新增事件。重設、確認、停用股票都不清除歷史。

本版沿用 1.0.0（先前標為 2.4.0）的設定與提醒歷史格式（儲存格式 v2），新增可選的每日成功掃描日期，不重設追蹤高點或歷史；舊背景監控開關不再生效。先前 2.3.0 的設定（儲存格式 v1）也會自動讀入；舊版有觸發時只匯入既存觸發，不補造過去事件。新設定與事件一起保存，儲存失敗不發出成功提醒。請勿換回僅支援儲存格式 v1 的舊程式；發行版號與資料格式版本分開管理。

## 20 日區間與 MA20

| 指標 | 本套件計算 | 用途 |
| --- | --- | --- |
| 20 日區間支撐／壓力 | 最新交易日前 20 個已收盤交易日的最低／最高價，不含最新交易日 | 觀察前期區間上下邊界 |
| MA20／SMA20 | 最近 20 個有效交易日收盤價平均，含最新日 K；盤中可能變動 | 觀察平均價格與趨勢 |

例：前期最低 90、最高 120，最近 20 日收盤平均 105，則區間上下邊界為 90／120，MA20 為 105。

20 日是本套件選定的短期區間，不是市場唯一的支撐壓力定義。支撐／壓力也可由反覆測試的價位、前波高低或其他圖表工具判讀。參考 [Fidelity 支撐與壓力說明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/support-and-resistance) 與 [Schwab 技術分析介紹](https://www.schwab.com/learn/story/filtering-market-using-technical-analysis)。

## 計算與資料基準

- SMA 為 N 個有效交易日收盤價平均；EMA 使用首 N 筆 SMA 起始值與 `2/(N+1)` 平滑係數。
- RSI 使用 Wilder 平滑，需 N+1 筆收盤價；完全持平時本套件定義為 50。
- 布林採母體標準差（除以 N），上下軌為 SMA ± 2σ。
- Classic Pivot 的第三層採 `P ± 2(H−L)`，與 Traditional 第三層不同。完整說明見 [TradingView 官方公式](https://www.tradingview.com/support/solutions/43000521824-pivot-points-standard/)。
- 52 週近高／低點採區間兩端各 15%；優先使用供應商數值，缺漏時用目前可取得資料中最近 364 日的高／低點，因此新上市或歷史不足的股票可能未滿 52 週。
- 「高於／低於均線」是目前位置，不代表今天剛發生交叉。篩選多條條件採 OR。
- 價格採 Yahoo OHLC，可能含供應商拆股調整，非含息還原報酬。買賣紀錄保留原始成交價；發生拆股時不應直接將原始成交價與歷史 K 線縱軸視為同一基準。
- OHLC 全空且無成交量的佔位資料安靜略過，不把休市或尚無交易當成錯誤；不據此宣稱已辨識交易所假日。部分缺值、有成交量卻無價格、非有限數或高低關係異常的日 K 仍會略過並提示。404 仍顯示代碼／市場檢查提示，不當成休市吞掉。盤中或未知收盤狀態不標成已收盤；日期使用交易所時區。
- 主圖／總覽為載入時的行情快照；移動停利清單有獨立的最新檢查時間。重新整理／重新載入可更新圖表。

## 安裝

將本目錄 `addon.zip` 透過 Wealthfolio「設定 → 擴充功能 → 從檔案安裝」更新。需要支援 SDK 3.8.0 的主程式；若主程式沒有儲存 API，介面會顯示錯誤並停用提醒設定。

1.0.1 沿用既有權限，不增加權限。先前開發版本已新增唯讀的 `activities:getAll` 權限，用來呈現你的買賣點；更新時請在主程式確認此權限。既有權限是 `accounts:getAll`、`portfolio:getHoldings`、`network:request`。設定儲存與套件內提示使用 SDK 基礎 API。只有股票代碼與行情查詢日期送至 Yahoo，交易紀錄不送至 Yahoo。

## 版本管理

從 1.0.0 起採用 [語意化版本（SemVer）](https://semver.org/lang/zh-TW/)，以 `主版號.次版號.修訂號` 表示：

| 變更 | 範例 | 本套件判斷方式 |
| --- | --- | --- |
| 修正錯誤、文案或相容的介面微調 | 1.0.0 → 1.0.1 | 不增加新能力，也不破壞既有用法 |
| 新增相容功能 | 1.0.1 → 1.1.0 | 增加新指標或提醒方式，原設定仍可正常使用 |
| 不相容變更 | 1.1.0 → 2.0.0 | 改變既有介面契約、計算定義或設定用法，造成相容性中斷 |

- `0.x.y` 表示尚未穩定的初期開發，不用來表示 1.0.0 之後的小修正。
- 每次修改不必立即升版。開發中先累積於 [CHANGELOG.md](CHANGELOG.md) 的「尚未發行」，準備交付新版安裝包時再依整批變更升版。
- 已交付的版本之後若有內容變更，使用新版本，不覆蓋同版內容；測試版可用 `1.1.0-beta.1`。
- 每次發行同步 `package.json`、`package-lock.json` 與 `manifest.json`，重新封裝 `addon.zip`。Git commit 記錄日常修改，正式發行時可建立 `v1.0.1` 這類標籤，兩者不等於每次都要升主版號。
- 本次依使用者要求將先前的 2.x 編號一次性重定為 1.0.0；後續依上述規則遞增，不再反覆重設。此編號重定不能視為一般由小到大的自動更新，主程式安裝行為仍需以實際匯入檔案確認。

## 開發與驗證

```sh
npm install
npm run type-check
npm test
npm run bundle
```

`bundle` 會重新建置並產生全新封裝，避免舊檔案殘留。`dist/` 與 `manifest.json` 包含於封裝，不含預覽資料。

本機模擬資料預覽：執行 `npm run preview:fixtures`，開啟終端顯示的本機網址並加上 `/tests/preview.html`。這個頁面使用合成行情、假交易與記憶體儲存，不會連到真實帳戶，也不是正式安裝。

專案原有的 `lint` 指令尚未配置 ESLint；本次以包含測試檔的 TypeScript 檢查、Vitest 與建置驗證為準。
